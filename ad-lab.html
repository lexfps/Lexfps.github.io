Active Directory Help Desk Lab

I built a virtualized Windows domain environment using Windows Server 2022 and Windows 10 in Oracle VirtualBox. The lab simulates a small business IT environment and provides hands-on experience with Active Directory, DNS, Group Policy, user and group administration, shared resources, domain authentication, and common Tier 1 help desk troubleshooting scenarios.

Overview

Project Objective

The goal of this project was to build a functional Windows Active Directory environment and practice administrative and troubleshooting tasks commonly performed by help desk and desktop support technicians.

I configured a Windows Server domain controller, created an Active Directory domain, provisioned users and security groups, joined a Windows workstation to the domain, configured Group Policy and shared resources, and then intentionally created common support issues to diagnose and resolve.

Tier 1 Simulation

Help Desk Scenarios

After completing the environment, I intentionally simulated common support issues and documented the troubleshooting and resolution process for each scenario. Select a ticket below to view the full workflow.

Ticket 01

Forgotten Password

+
Issue

Domain user could not authenticate after forgetting their password.

Resolution

Reset the password through Active Directory Users and Computers and required a password change at next logon.

Verification

Confirmed the password-change requirement and verified successful domain login using the new credentials.

Ticket 02

Account Lockout

+
Issue

User account became locked after multiple unsuccessful login attempts.

Resolution

Located the account in Active Directory, confirmed the lockout, and manually unlocked the account.

Verification

Confirmed that the user could successfully authenticate again.

Ticket 03

Employee Offboarding

+
Request

Employee account required deactivation and removal of existing department access.

Resolution

Disabled the Active Directory account, moved it to the Disabled Users OU, and removed department security-group membership.

Result

Account was deactivated and access associated with the employee's former department was removed.

Ticket 04

New Employee Onboarding

+
Request

New IT employee required a domain account and access to appropriate department resources.

Configuration

Created the account in the IT OU, assigned GG_IT_Users membership, and configured domain authentication.

Verification

Confirmed successful login, access to the IT share, and denial of unauthorized HR resources.

Ticket 05

DNS Resolution Issue

+
Issue

CLIENT01 was unable to resolve the domain controller hostname.

Troubleshooting

Used nslookup and network settings to identify an incorrect DNS server configured on the client.

Resolution

Restored 192.168.10.10 as the DNS server and verified successful name resolution to DC01.

Ticket 06

Shared Folder Access / Group Membership

+
Issue

Finance user was unable to access the department shared folder.

Troubleshooting

Reviewed Active Directory group membership and determined that the user was missing GG_Finance_Users.

Resolution

Restored the security-group membership, refreshed the user's authentication session, and verified access.

Troubleshooting Tools

Commands Used

ipconfig /all Reviewed client IP and DNS configuration.
ping Tested IP connectivity between systems.
nslookup Tested DNS name resolution.
whoami Verified the currently authenticated identity.
whoami /groups Verified the user's current security groups.
gpupdate /force Forced Group Policy processing.
gpresult /r Verified applied Group Policy Objects.
ipconfig /flushdns Cleared the local DNS resolver cache.

Problem Solving

Challenges & Solutions

Separating Connectivity From DNS Resolution

During the DNS troubleshooting scenario, CLIENT01 retained direct IP connectivity to DC01 while DNS name resolution was intentionally broken. I used nslookup and the client's IPv4 configuration to isolate the problem to DNS rather than treating it as a complete network outage.

Group Membership Not Updating Immediately

After restoring a user's Finance security-group membership, the group did not immediately appear in the user's current Windows session. I confirmed the account configuration in Active Directory and completely signed the user out before authenticating again.

The new logon generated an updated security token, and GG_Finance_Users then appeared successfully when verified with whoami /groups.

Verifying Group Policy Deployment

Rather than assuming the mapped-drive policy had applied correctly, I used gpupdate /force and gpresult /r on CLIENT01 to verify that the IT Drive Mapping GPO was actually being processed for the intended user.

Reflection

What I Learned

This lab strengthened my understanding of how Active Directory, DNS, Group Policy, Windows authentication, security groups, and shared resources interact within a domain environment.

Troubleshooting intentionally created problems also helped me practice isolating an issue before making changes. I gained hands-on experience distinguishing DNS problems from general connectivity problems, investigating permissions through group membership, verifying Group Policy application, and resolving common user-account issues.
